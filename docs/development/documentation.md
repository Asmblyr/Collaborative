# Проверки и сопровождение документации

## Источники истины

| Содержание                               | Где редактировать                                                    |
| ---------------------------------------- | -------------------------------------------------------------------- |
| Пользовательское поведение, ограничения  | docs/features и docs/guide                                           |
| Границы безопасности, результат проверки | docs/security                                                        |
| HTTP маршруты                            | Core handlers; AST scanner читает фактические объявления             |
| Требования доступа HTTP                  | docs/reference/endpoints.json после проверки handler/service         |
| Детальные OpenAPI схемы                  | scripts/docs/http-contracts.mjs                                      |
| SDK/Kit методы и типы                    | packages/sdk/src, packages/kit/src; TypeDoc                          |
| Руководства SDK/Kit                      | README/HOOKS/FIELDS внутри пакетов; копируются генератором           |
| Старые исследования                      | design/research/reviews/ideas; не переписывать историю задним числом |

## Команды

```powershell
pnpm docs:generate
pnpm docs:check
pnpm docs:build
pnpm typecheck
pnpm lint
pnpm test:all
```

`docs:check` проверяет соответствие статических Core маршрутов каталогу, отсутствие устаревших записей, актуальность OpenAPI/матрицы и копий package guides. AST-покрытие не доказывает исполнение авторизации: для этого нужны интеграционные проверки. TypeDoc пересобирается перед сайтом; сборка проверяет Markdown-ссылки. Динамические plugin routes и внутренний oidc-provider вынесены в явно описанные исключения.

Новый endpoint: добавить декларацию доступа, описать вход/выход при расширении подробного OpenAPI контракта, обновить функциональную страницу, добавить отрицательную проверку прав. Не маскировать неизвестную схему как полный typed API.

Изменение поведения: в том же изменении обновить страницы, контракты и примеры; обозначить ограничения. Исторический отчёт сохраняет свою дату. Не помечать функцию готовой только по существованию design-файла.

## Тестовые данные

Все интеграционные тесты запускаются через `node scripts/test.mjs <suite>`. Runner создаёт локальную одноразовую БД, применяет миграции и удаляет её в finally. Он запрещает удалённые адреса; прямой запуск файлов без isolation marker запрещён. Не тестируйте удаление/выдачу прав на рабочей БД.

Live BFF/browser и LavinMQ требуют отдельного окружения. Указывайте отдельно, какие проверки пропущены. Для изменённого сценария выбирайте достаточный набор; полный прогон — для такого общего аудита и изменений общих контрактов.
