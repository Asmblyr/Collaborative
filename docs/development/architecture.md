# Архитектура и правила

| Часть              | Ответственность                                                        |
| ------------------ | ---------------------------------------------------------------------- |
| apps/core          | Fastify API, доменные сервисы, Knex/PostgreSQL, интеграции             |
| apps/ui            | Next.js, BFF сессии, shadcn-интерфейс                                  |
| packages/contracts | Общие типы/валидируемые публичные контракты без серверных зависимостей |
| packages/sdk       | HTTP-обёртка для внешнего клиента и UI                                 |
| packages/kit       | Контракт расширений, H3, контекст caller, build tools                  |
| plugins            | Локальные примеры расширений                                           |

Core не вызывает собственный HTTP через SDK. HTTP, Kit и MCP обращаются к общим авторизованным сервисам. Knex сам не знает пользователя и не закрывает таблицы: перед SQL обязательны проверки Core. Привилегированный код и DB credentials входят в доверенную границу.

Данные находятся в одной схеме `public`; системная структура задаётся миграциями. Зарезервированные префиксы охраняются на операциях изменения схемы. Permissions отдельно от метаданных отображения, поиска и workspaces.

## Читаемость

Тонкие роуты/страницы, отдельные validation/service/repository на реальных границах. Осмысленные промежуточные переменные, фигурные скобки, отсутствие вложенных тернарников. Prettier форматирует, но не заменяет выделение смысловых блоков.

На 250 строках пересмотреть ответственность файла, после 350 разделить либо обосновать. Миграции/генерируемые справочники могут быть исключением. Не вводить механизм расширения для гипотетического сценария без потребителя.

Полные обязательные правила — корневой `AGENTS.md`, Next-specific правила — `apps/ui/AGENTS.md`.
