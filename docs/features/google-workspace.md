# Google Workspace в ассистенте

Опциональный пакет `@asmblyr-collaborative/plugin-google-workspace` добавляет поиск файлов
Google Drive, чтение текстовых файлов и Google Docs, структуру Google Sheets
и чтение диапазонов. Запись готовится как предложение с конкретными данными;
пользователь проверяет его в правой панели и нажимает «Подтвердить изменение».

## Настройка установки

В Google Cloud включите Drive API и Sheets API. Создайте отдельный OAuth web client
для ассистента с External audience. Добавьте redirect URI
`https://admin.example.com/connections/google/callback`; для локальной разработки
допустим `http://localhost:3000/connections/google/callback`.

В `/admin/settings/integrations` откройте Google Workspace, задайте client ID,
redirect URI и write-only client secret, затем включите подключение.
На сервере должен быть настроен [ключ local или Yandex KMS](./settings.md).
Проверка конфигурации проверяет параметры и шифрование. Корректность client secret
и разрешённого callback проверяется при реальном OAuth-подключении.

Альтернатива — `GOOGLE_WORKSPACE_ENABLED=true`, `GOOGLE_WORKSPACE_CLIENT_ID`,
`GOOGLE_WORKSPACE_CLIENT_SECRET`, `GOOGLE_WORKSPACE_REDIRECT_URI` в конфигурации Core.
Наличие любого из этих env-параметров делает всю группу readonly в админке.
Пакет включается в корневом `asmblyr.plugins`, capability `connections.google`
подтверждается в `asmblyr.pluginPermissions`. Исключение пакета убирает инструменты,
сохраняя личные подключения до явного отключения.

Запрашиваются `openid`, `email`, `profile`, полный `drive` и `spreadsheets`.
Это доступ к разрешённым пользователю файлам, включая общие диски согласно их ACL.
В режиме Google Testing подключаются только тестовые пользователи; refresh tokens
для этих scopes обычно истекают через семь дней. Для публичного приложения
нужны проверка Google и опубликованная политика конфиденциальности; администратор
Workspace может запретить стороннее приложение. См. [OAuth Google](https://developers.google.com/identity/protocols/oauth2)
и [scopes Drive](https://developers.google.com/workspace/drive/api/guides/api-specific-auth).

## Личное подключение

Пользователь открывает значок подключений в ассистенте или
`/settings?tab=applications`, нажимает «Подключить Google» и предоставляет согласие
в Google. Подключение принадлежит активному человеку и не доступно сервисным
аккаунтам, другим пользователям или администратору через интерфейс. Вход в Asmblyr
и Google API-подключение — разные потоки: email не связывает профили автоматически.

OAuth использует authorization code, PKCE S256, state, nonce, проверку issuer,
ID token и subject через `openid-client`. Поток привязан к пользователю, конфигурации
клиента и HttpOnly browser cookie, действует десять минут и принимается один раз.
Callback требует действующую сессию Asmblyr. Отключение во время callback отменяет
поток. Токены и PKCE proof хранятся зашифрованными в PostgreSQL, с отдельным AAD
на запись; смена local/KMS пересчитывает и эти секреты в одной транзакции.
При недоступности KMS нет автоматического перехода на local.

Токены обновляются на сервере; `invalid_grant`, смена OAuth client или отзыв доступа
требуют подключения заново. Токены не передаются модели, плагину или браузерному
JavaScript. Отключение удаляет локальные секреты и предложения, затем пытается
отозвать Google grant. При неудаче UI просит также отозвать его в аккаунте Google.
Недоступность шифрования отражается флагом `unavailable` в личном статусе;
метаданные аккаунта и локальное отключение остаются доступны.
Уже выполняющийся внешний запрос нельзя гарантированно отменить.

## Инструменты и ограничения

| Инструмент       | Поведение                                                                                                                               |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `find-files`     | Поиск по имени, 25 файлов на страницу, source URLs и следующий page token                                                               |
| `read-text`      | Текстовые файлы и plaintext export Google Docs, до 30 КБ с явной отметкой обрезки                                                       |
| `describe-sheet` | Название таблицы, имена и размеры вкладок                                                                                               |
| `read-cells`     | Явный A1 прямоугольник до 500 ячеек, ответ до 36 КБ                                                                                     |
| `propose-write`  | Подготовка создания/замены текстового файла, переименования, перемещения в корзину, создания таблицы, замены ячеек или добавления строк |

Значения Sheets записываются в режиме RAW: строки не становятся формулами.
Размер прямоугольника должен совпадать с массивом значений. `append_cells`
добавляет строки после логической таблицы, найденной Google в указанном диапазоне,
и сдвигает последующие строки; это отображается в подтверждении.
Редактирование содержимого нативного Google Docs, произвольные бинарные документы,
OCR, Slides, файловые вложения и постоянная индексация в этот пакет не входят.

Инструменты доступны только при активном личном подключении, одобренной capability
и включённом доступе к данным в «Подключениях ассистента». Контекст страницы
включается отдельно и для Google не обязателен. Подключение позволяет пользоваться чатом без
прав на коллекции, но не добавляет права чтения данных Core. Коллекция, выключенная
из MCP, остаётся закрытой; личные инструменты Google продолжают работать.
Документы и ячейки являются недоверенными данными. Запрошенные фрагменты передаются
настроенному AI-провайдеру; сам grant не запускает обход всех файлов.

Запросы Drive используют `www.googleapis.com/drive/v3`, а Sheets —
`sheets.googleapis.com/v4`, включая создание таблиц и запись ячеек.
Ошибки инструментов различают необходимость переподключения, отказ Google,
отсутствующий файл, ограничение частоты запросов, неверные параметры и сетевой сбой.
Сообщения берутся из фиксированного списка: содержимое ошибок Google и токены
модели не передаются. Сбой запроса не доказывает отсутствие доступа к файлу.

Предложение действительно двадцать минут, до 32 ожидающих на пользователя.
Его данные зашифрованы, подтверждение привязано к тому же подключению и владельцу.
Модель не получает инструмент подтверждения; HTTP подтверждает сохранённый payload,
не принимая новое содержимое от браузера. Перед записью проверяются версия файла
или значения диапазона. Между этой проверкой и Google write остаётся небольшое
окно: API не предоставляет общей транзакции с PostgreSQL.

Подтверждение принимается один раз. Сбой после отправки Google write даёт
`uncertain`; нужно проверить файл перед новым предложением. Перезапуск во время
записи оставляет `executing`, повтор недоступен. Журнал содержит только провайдера,
вид операции и результат. По истечении TTL предложения и flow удаляются очисткой.

Карточка показывает отдельные исходы: «Выполнено», «Отклонено», «Не выполнено»
и «Проверьте результат». Последний используется для `uncertain` и оставшегося
`executing`: он не утверждает, что Google не изменил файл. У изменившейся цели
показывается причина отказа, предлагается подготовить новое изменение.
Кнопка «Посмотреть результат» остаётся доступной после завершения; в правой панели
можно просмотреть исходное предложение, краткий итог и обновить статус.
«Обновить статус» выполняет только GET, повторной записи нет. При потере ответа
подтверждения UI сверяет состояние с сервером и сохраняет запрет второй отправки.

Для успешной операции Core сохраняет зашифрованный ограниченный итог: ссылку на
файл/таблицу, число изменённых ячеек/строк и диапазон, если Google их вернул.
Произвольный ответ провайдера не сохраняется; ссылки строятся из ID файлов на
доменах Google. У существующей цели ссылка доступна и при неизвестном результате.
Созданный файл получает ссылку только после подтверждённого ответа с его ID.
Отклонение сохраняет статус `cancelled` и не отправляет запрос записи в Google.
Просмотр предложения и итога ограничен прежними двадцатью минутами, владельцем
и тем же подключением. После истечения или отключения аккаунта серверный просмотр
недоступен. Восстановленная история чата не активирует старые карточки.

Контракты Core `/connections/google`, OAuth start/callback и owner-bound
`/connections/google/writes/:id` описаны в [HTTP API](../reference/http.md).
Плагин использует обычные H3 file routes и `defineModelContext`; схемы генерирует Kit.
Проверки с временной БД и локальным Google adapter: `node scripts/test.mjs core-connections`.
