# Внешний MCP

В настройках → «Приложения» показан адрес `/api/mcp`. Добавьте его в MCP-клиент
с поддержкой Streamable HTTP и OAuth, войдите обычным аккаунтом Collaborative,
выберите коллекции и при необходимости разрешите создание и изменение записей.
Пароль или ключ администратора передавать клиенту не нужно.

В локальной Windows браузер может разрешать `.localhost` самостоятельно, а
обычный MCP-клиент использует системный DNS. При необходимости добавьте в
`C:\Windows\System32\drivers\etc\hosts` строку
`127.0.0.1 collaborative.asmblyr.localhost`. Для изменения файла нужны права
администратора Windows. На удалённой установке используется обычный DNS.

Поддерживается MCP **2025-11-25** установленного SDK и согласованные им более
ранние версии. Ответы JSON, транспорт без состояния. SSE-подписки, транспортные
сессии и протокол 2026-07-28 не реализованы. Метаданные авторизации доступны на
публичном домене админки: `/.well-known/oauth-protected-resource/api/mcp` и
`/.well-known/oauth-authorization-server`.

## Общее ядро и права

Ассистент сайта и HTTP используют одну фабрику MCP-сервера, определения
инструментов, диспетчер, сервисы данных и запись items. Второй реализации нет.
Внешний MCP v1 публикует встроенные инструменты данных; карточки интерфейса,
действия плагинов и личные подключения Google в это разрешение не входят.

Каждый вызов проверяет активность человека и исходного сеанса, разрешения
подключения, текущие права на коллекцию, действие, поля и строки, а также
`mcp.enabled`, включая superuser. Разрешение клиента только сужает права
пользователя. Связанные коллекции тоже должны быть выбраны, доступны для чтения
и включены в MCP. Сохраняются ID коллекций: пересоздание с тем же именем не
наследует доступ. Системные пользователи, закрытые данные профиля, credentials
и произвольный SQL не публикуются.

В первой версии выбранная коллекция должна быть доступна для чтения. Обновление
полей без права чтения не поддерживается из-за проверки исходных значений.
Выбор коллекции не выдаёт права на пространство или администрирование.

## Инструменты

| Задача                            | Инструменты                                                   |
| --------------------------------- | ------------------------------------------------------------- |
| Структура                         | `list_collections`, `describe_collection`                     |
| Чтение                            | `search_items`, `read_item`, `count_items`, `validate_filter` |
| Аналитика доступных строк         | `aggregate_items`                                             |
| Создание записи                   | `create_item`                                                 |
| Подготовка и применение изменения | `prepare_update`, `update_item`                               |

Сначала вызовите `describe_collection`. Схема содержит типы, обязательность,
nullable, читаемые связи, пути фильтрации и подсказки прав create/update на поля.
Условия на строки проверяются при выполнении. Описания сохраняются для
подключения в PostgreSQL и доступны на разных репликах Core. Чтение и аналитика
используют те же лимиты и точные числа, что [ассистент сайта](./assistant.md).
Предпросмотр значений ограничен; массового экспорта здесь нет.

Запись принимает технические имена полей и ID связей, использует штатную
валидацию, историю и транзакционные hooks. Удаление, изменение схем и вложенное
создание не поддерживаются. При создании укажите ключ только для коллекции с
текстовым ID; остальные типы ключей генерирует Core по штатным правилам.
`prepare_update` возвращает исходные типизированные
значения изменяемых полей: передайте их без изменений как `expectedValues`.
Конкурентное изменение даёт `ITEM_CHANGED`; сначала проверьте актуальную запись.

Для каждой новой операции задавайте уникальный `operationId`. После сетевой
ошибки повторяйте **те же аргументы и ID**. PostgreSQL сериализует дубликаты и
возвращает сохранённые метаданные результата. Другие аргументы с прежним ID дают
`OPERATION_REUSED`. В кэше нет значений полей. Гарантия охватывает запись Core и
транзакционные hooks; внешние нетранзакционные эффекты в hooks запрещены.

## Срок действия и отзыв

OAuth-клиент регистрирует точный HTTPS callback или HTTP loopback. Вход требует
явного согласия на сайте, PKCE S256, одноразового кода на 60 секунд и точного
адреса ресурса MCP. Токены непрозрачные, в БД хранятся хэши. Они не подходят для
обычного Core API. Cookie не авторизует `/api/mcp` и его OAuth endpoints.
Браузерный внешний клиент может использовать origin зарегистрированного
callback с явным bearer и без cookies.

Access token действует до пяти минут; клиент продлевает его вращаемым refresh
token. Подключение действует до 30 дней, но не дольше исходного сеанса.
Повторное использование погашенного кода или refresh отзывает подключение.
Блокировка пользователя, отзыв сеанса или «Отозвать доступ» в «Приложениях»
останавливают вызовы и продление. Вход через внешний identity provider использует
того же пользователя Collaborative и его права. Сервисные аккаунты в v1 не
поддерживаются.

Интеграционные тесты используют официальный MCP-клиент и сравнивают HTTP с
внутренним адаптером. Проверяются права, условия строк, выбор коллекций, запись,
конфликты, повторы, вращение и отзыв. Запуск:
`node scripts/test.mjs core-mcp` через изолированную локальную тестовую БД.
