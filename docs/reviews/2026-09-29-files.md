# Files review — 2026-09-29

## Scope

Separate file resource, S3/YC drivers, federation token exchange, private admin
library with native editor, metadata audit and recoverable storage lifecycle.
No user collection/file relations or image transformation pipeline yet.

## Review

- Source modules have one purpose; new production files are below 150 lines.
- Superuser checked before Core consumes raw uploads; no generic item access.
- Browser proxy checks origin, bounds uploads, renews sessions and streams downloads.
- IAM/JWT/static credentials never returned to UI, metadata or logs.
- HTML/SVG are attachment-only. Raster previews require content signature checks.
- Persist upload intent and deletion tombstone across storage/DB failures.
- No-op metadata updates have no audit; deleted file audit survives.
- Cloud bucket is private, static-key authentication disabled, 1 GiB dev limit.
- Exact federation subject, dedicated audience and isolated K8s ServiceAccount.
- No folder-wide IAM grant; no Kubernetes workload, Role or RoleBinding created.
- Reserved metadata migration is additive. Rollback refuses populated tables.
- Repo is entirely untracked, so git diff is not a meaningful whole-change review;
  changed source files were read directly. No sibling projects changed.

## Cloud access completed

The user explicitly approved the previously blocked read/write base bucket ACL.
Only the dedicated service account received those grants; the final policy limits
object operations to `files/*`. Wrong subject and audience exchanges were rejected.
Anonymous GET, bucket listing, policy PUT and outside-prefix GET/PUT were denied.
Outside-prefix GET used an existing synthetic object, not a missing-key 404.
The probe object was removed and original policy restored after the check.
YC allows reading the bucket policy via its base read ACL; no policy write granted.

Repeat verification: `infra/files/verify-federation.ps1`; real BFF test:
`TEST_FILES_CLOUD=1 pnpm --filter @asmblyr/core exec tsx --test test/files-ui.integration.test.ts`.
Tests clean only their own data. Browser file chooser automation was unavailable
because Chrome extension file-URL access is disabled; no extension settings changed.

## Limits

25 MiB bounded-buffer uploads, streamed downloads, no automated orphan cleanup or
audit retention. Only superusers for now; file permissions and relation fields are
future work. Generic S3 adapter typechecked but not tested against another live
S3 provider. Local token source uses the developer kubeconfig; production rejects
that source and requires a projected OIDC token file.
