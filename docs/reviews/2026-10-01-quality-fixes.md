# Исправления после ревью: читаемость и целостность

Дата: 2026-10-01. Исходные замечания: [код-ревью](2026-10-01-code-quality.md).

## Читаемость и переиспользование

- `assistant/data-tool-input.ts`: отдельные типы результата для чтения, поиска и
  подсчёта; явный `switch`; именованные проверки полей, чисел и наследуемых
  параметров. Проверка доступности столбцов вынесена в `data-projection.ts`.
  Сохранены ограничения количества полей, размера выдачи, страниц и текста.
- `assistant/context-input.ts`: парсер контекста таблицы возвращает проверенный
  объект вместо приведения исходного объекта к типу результата.
- `shared/input.ts`: общие примитивы валидации больше не принадлежат модулю
  сервисных аккаунтов. Совместимый экспорт `AuthInputError` сохранён.
- Редакторы поля и связи разделены на форму, состояние/сохранение и отдельные
  настройки обратной связи и поведения при удалении. Убрана цепочка вложенных
  тернарных операторов при составлении команды создания связи.
- `@asmblyr/contracts`: единые типы формы, условий видимости, отображения поля,
  повторяемых блоков и отображения значений. Там же общая конфигурация очистки HTML.
  Пакет не импортирует React, Knex или настройки сервера; сборка ему не нужна.
  DTO коллекций пока различаются: Core возвращает структуру, UI дополняет её доступом.
- `http-request.ts`: единая обработка JSON и ошибок HTTP, включая статус, код,
  `requestId` и сигнал отмены. Обёртки явно возвращают либо envelope, либо `data`.
  `accessRequest` перенесён из файла типов в `lib`.
- При чтении списка каталог используется повторно для подписей записей;
  настройки коллекции не запрашиваются заново только ради основного ключа.
- Prettier закреплён в зависимостях. В `AGENTS.md` добавлены требования к явным
  ветвлениям, контрактам парсеров и разделению обязанностей. Форматирование
  применяется к затронутым файлам; весь репозиторий массово не переформатирован.

## Явные ограничения

- PostgreSQL `CREATE/DROP INDEX CONCURRENTLY` выполняется отдельно от транзакции
  настроек поля. Если построение индекса не удалось, UI сообщает, что настройки
  сохранены, и предлагает повторить сохранение. Для нового поля повтор не создаёт
  второй столбец. Изменение индекса вместе со схемой не является атомарным.
- Ограничители запросов хранятся в памяти процесса. BFF-клиенты разделяют IP;
  несколько реплик Core требуют общего ограничения на ingress. `trustProxy`
  для произвольных forwarded-заголовков не включён.
- Readiness проверяет миграции и критичные metadata, а не каждое возможное
  ручное повреждение структуры БД.
- История каскадных изменений PostgreSQL остаётся отдельной задачей из исходного
  ревью. Миграции и механика каскадного аудита в этой работе не менялись.
- Live BFF/browser integration scripts, облачный S3/OIDC, платные AI-вызовы,
  production build UI и нагрузка в этом этапе не проверялись. Браузерная проверка
  касалась локальных несохранённых черновиков, без изменения рабочих данных.
