# Фильтры записей

## Взаимодействие

Конструктор открывается в popover над таблицей. Простое условие читается
как одна строка: **поле → оператор → значение**. Каждая часть редактируется
на месте. Дополнительные настройки показываются только когда нужны.

- «Добавить условие» открывает поиск по полям и связям. Поиск находит также
  поля связанных коллекций. Стрелка справа от связи открывает её поля;
  название связи добавляет условие с выбором конкретных записей.
- В выборе записей есть поиск и страницы по 25 записей. «Равно» выбирает
  одну запись, «одна из» — до 20. Выбор сохраняется при поиске и смене страниц,
  а подписи выбранных записей загружаются также при открытии фильтра из URL.
- Для текста начальный оператор — «содержит». Смена совместимого оператора
  сохраняет введённое значение. Учёт регистра — отдельный переключатель.
- Текст и числа вводятся в строке; даты, диапазоны и списки — в компактном
  окне значения. Элементы списка вводятся отдельно: запятая внутри значения
  не разделяет его на два элемента.
- Группа И/ИЛИ добавляется из того же меню. Вложенность обозначается левой
  линией. При одном условии переключатель корневой группы скрыт.
- Изменения являются черновиком до «Применить». Закрытие окна отменяет
  черновик. «Сбросить» убирает применённый фильтр.
- Вкладка «Сохранённые» использует существующие персональные пресеты в Core.

## Контракт и границы

Формат HTTP API не меняется: дерево `logic` / `children`, условия
`field` / `op` / `value` и `quantifier` для связей со многими записями.
Состояние применённого фильтра остаётся в URL.

Для M2O выбор записей использует прямое поле внешнего ключа. Для O2M/M2M —
первичный ключ связанной коллекции: «включает любую из» передаётся как
`in` + `some`, «не включает ни одну из» как `in` + `none`. Это исключает
совпадение при наличии хотя бы одной выбранной связи. Прежние фильтры
`notIn` + `some` сохраняют свою отдельную семантику и обычный редактор поля.

Поддерживается один переход по связи M2O, O2M или M2M. Для O2M/M2M каждое
условие проверяет наличие или отсутствие подходящей связанной записи.
Два условия внутри И не гарантируют, что их удовлетворяет **одна и та же**
связанная запись. Группы с таким требованием потребуют отдельного расширения
контракта Core.

Текущие ограничения Core: 20 условий, 3 уровня групп, 30 узлов, до 20 значений
в списке и 8192 символов JSON. UI проверяет их перед переходом, а также
пустые группы, незаполненные значения, UUID, числовые границы и даты.
Core остаётся источником проверки прав и допустимости запроса.
