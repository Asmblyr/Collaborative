# Таблицы связей и параметры промежуточной записи

Реализовано 2026-09-30. O2M/M2M отображаются в карточке записи, во вкладке
«Связи». Настройки: Коллекции → поле связи → «Связанные записи».

## Настройки

`PUT /collections/:collection/fields/:field/presentation` принимает необязательный
объект `relation` для виртуальных O2M/M2M полей:

```json
{
  "relation": {
    "layout": "table",
    "columns": ["name", "email", "active"],
    "labelField": "name",
    "sortField": "name",
    "direction": "asc",
    "pageSize": 10,
    "allowCreate": true,
    "allowSelect": true
  }
}
```

- Виды: `table` и `list`. По умолчанию используется таблица.
- До 12 физических столбцов целевой коллекции в заданном порядке. Пустой список
  означает автоматический выбор до трёх полей. Изменение порядка — кнопками вверх/вниз.
- Подпись: выбранное поле или настройка целевой коллекции. Составные шаблоны пока
  не реализованы. Подпись учитывается и при выборе существующей записи.
- Страница: 10, 25 или 50 строк. Сортировка из настроек или временная по заголовку.
- Создание и выбор существующих записей можно скрыть по отдельности. Эти флаги —
  настройки интерфейса: доступ к API определяется обычными политиками.
- Удалённые/недоступные столбцы исключаются при чтении. Если не осталось столбцов,
  выводится основной ключ. Недоступная сортировка заменяется основным ключом;
  явный запрос сортировки по закрытому полю получает 403.

Настройки хранятся в имеющемся JSONB `asmblyr_relation_aliases.presentation`.
Новых таблиц/миграций нет. PUT заменяет presentation целиком, как и прежде;
для сброса используется `{}`. Сохранение настроек доступно superuser.

## Данные и безопасность

`GET /items/:collection/:id/relations/:field` сохраняет `id`, `linkId`, `label`,
`abilities` и страницу; дополнительно возвращает `values` для выбранных доступных
столбцов и эффективные `display` settings. Поддерживает `q`, `page`, `limit`,
`sort`, `direction`. Поиск действует по доступным поисковым полям целевой коллекции.
Сортировка стабильна за счёт ключа целевой записи и ключа связи.

На уровне SQL выбираются только доступные столбцы. Права на alias и целевую
коллекцию проверяются по существующему контракту. Для O2M нужен read на FK.
Чтение M2M через alias само по себе не открывает атрибуты junction.

Клик/Enter на строке открывает обычный редактор целевой записи, включая readonly.
Меню строки позволяет отвязать запись и, для M2M, открыть параметры связи.
Отвязка удаляет junction или очищает O2M FK; целевая запись остаётся.

## Параметры M2M

Для обычных полей промежуточной коллекции переиспользуются `ItemForm`, редакторы,
валидация, права и история. Автоматические FK в этой форме не редактируются.

| Метод | Путь относительно `/items/:collection/:id/relations/:field` | Назначение |
| --- | --- | --- |
| GET | `/links/:linkId` | Прочитать доступные поля принадлежащей этой записи связи |
| PATCH | `/links/:linkId` | Изменить атрибуты связи |
| POST | `/links/to/:targetId` | Привязать существующую запись с атрибутами |
| POST | `/records` | Создать целевую запись и связь: `{item, link}` |

Scoped endpoints проверяют принадлежность связи текущей записи, запрещают
подменять FK в payload и применяют grants промежуточной коллекции. Новая запись,
junction, file references и события сохраняются в одной транзакции. Ошибка
в обязательном поле/праве откатывает всю операцию. Повторная привязка через
`/links/to` возвращает 409; прежний batch attach сохраняет свою идемпотентность.

При наличии доступных для создания атрибутов выбор существующей записи открывает
форму параметров для одной связи. Создание новой записи — два шага в одном окне,
с общей финальной записью в БД. Если атрибутов нет, остаётся массовый выбор.

## Границы компонентов

Физический тип и input interface остаются в текущей модели поля. Таблица связей
использует общую проекцию `item-columns` и `ItemTableValue`, а параметры junction —
обычные формы полей. Настройки и runtime разделены на небольшие модули. Публичный
SDK/loader расширений на этом этапе не вводится.

Вложенный native dialog закрывает только собственное окно: события close/cancel
не закрывают родительский редактор. Его черновик сохраняется.

Следующие отдельные задачи: составные шаблоны, столбцы атрибутов junction прямо
в таблице, ручной порядок строк, repeaters, публичный контракт displays/interfaces.
