# Проверка присутствия — 3 октября 2026

## Контракт и границы

`POST /presence` связывает случайный UUID окна с текущей человеческой сессией.
Core сам определяет пользователя; дополнительные поля идентичности в теле
отклоняются. Область разрешает только известные страницы, коллекции и записи.
Read проверяется заново при каждом обновлении, включая условные права строки;
разделы настроек проверяют свой доступ, файловая библиотека требует superuser.
`DELETE /presence/:clientId` удаляет только окно вызывающей сессии и работает
после потери права read. Сервисный principal не может пользоваться обоими маршрутами.

В ответе есть публичные ID, имена, аватары и количество окон участников той же
области. Нет email, session ID, токенов или содержимого записи. Настройки поиска,
фильтры и произвольные URL не становятся областями присутствия. Ответы не кешируются;
UI-прокси использует существующую проверку origin и авторизацию через cookies.

Отметки разделены между процессами Core общей PostgreSQL. Срок — 30 секунд,
UI обновляет их раз в 5 секунд. Список объединяет пользователей, ограничен
50 профилями и отдельным total. Сессия допускает 32 активных окна; блокировка
сессии защищает этот предел при параллельных запросах. Истёкшие отметки очищаются
при heartbeat. Отозванные/истёкшие сессии и отключённые пользователи фильтруются
сразу при чтении. Изменённый read удаляет отметку при следующем heartbeat;
если клиент уже не обновляется, отметка исчезает после TTL. Это краткая подсказка
присутствия, без блокировок полей или доставки правок.

## Проверка

Набор `node scripts/test.mjs core-presence` запускается только в одноразовой БД.
Он проверяет SDK через HTTP второго процесса Core, объединение окон, изоляцию
коллекций/записей, безопасный повтор leave и невозможность удалить
чужую отметку. Отдельно проверяет отзыв read и условные права строки, отключение
пользователя, отзыв сессии, истечение отметки, параллельный лимит, отказ анонимному
и сервисному клиентам, запрет подмены идентичности и закрытых страниц.

UI-тесты проверяют отсутствие пересекающихся heartbeat, поздний ответ после
закрытия окна, восстановление после сетевой ошибки и безопасную очистку.
Ручная локальная проверка двух окон подтверждает аватарки и подсказку внутри
бокового диалога и уменьшение числа окон после закрытия второй вкладки. Проверено
также присутствие в заголовке настроек пользователей. Данные карточки при
проверке не изменялись. Нагрузочная проверка и production не охвачены.

Результаты: focused presence/access — 7/7; полный Core — 307 passed и один
пропущенный тест необязательной LavinMQ-интеграции; SDK — 13/13; UI — 92/92.
Typecheck, lint, сборка приложений и docs generate/check/build прошли.
