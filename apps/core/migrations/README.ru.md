# Миграции Core

<!-- languages -->

[English](README.md) · [Русский](README.ru.md)

<!-- /languages -->

Каталог содержит версионированные Knex-миграции .cjs системных таблиц. Core использует
public и резервирует префикс asmblyr\_, включая реестр asmblyr_migrations.

## Запуск

Задайте DATABASE_URL в apps/core/.env или окружении, затем из корня:

```sh
pnpm db:status
pnpm db:migrate
```

Для размещённой установки следуйте [эксплуатации](../../../docs/ru/development/operations.md).
Перед обновлением согласованно копируйте базу и файлы.

Pnpm db:rollback откатывает последнюю группу. Некоторые миграции отказываются
удалять таблицы/метаданные, пока от них зависят данные. Изучите конкретный down и
проверьте откат на одноразовой БД до применения к нужной установке.

## Новые миграции

- Добавляйте новый файл .cjs с timestamp и up/down. Не меняйте прежние миграции,
  включая форматирование: существующие базы уже выполнили их.
- Сохраняйте транзакционность, учитывайте строки, FK, индексы и defaults.
- Предпочитайте добавления; не удаляйте молча поля, права, аккаунты, историю и данные при откате.
- Проверяйте чистую установку и обновление на одноразовой БД через runner;
  см. [участие в проекте](../../../CONTRIBUTING.ru.md).

Плагинные plugin*&lt;namespace&gt;*&lt;local_name&gt; имеют отдельный реестр.
Их добавочные миграции принадлежат пакету; см.
[контракт плагинов](../../../docs/ru/development/plugin-actions.md).
Отключение не удаляет коллекции и не выполняет down.
