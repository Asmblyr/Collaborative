# Проверка федерации GitLab

[English](README.md) · [Русский](README.ru.md)

<!-- /languages -->

Пример проверки workload identity из GitLab CI. Настройте собственную федерацию:
issuer https://gitlab.com, защищённую ветку и точные идентификаторы проекта/job project.
Параметры в .gitlab-ci.yml должны соответствовать вашей установке.
Сервис без политик успешно входит, но не получает доступа к коллекциям.

## Запуск

1. Задайте CI/CD-переменную ASMBLYR_CORE_URL с HTTPS-адресом Core, доступным runner.
2. Запустите pipeline защищённой ветки main и ручную задачу federation-smoke.
3. Локальный runner может использовать http://127.0.0.1:3001 только в том же сетевом
   пространстве, что Core. Облачный runner не видит localhost вашего компьютера.

Audience и federation ID — несекретные идентификаторы. При другой установке замените
их в .gitlab-ci.yml. Задача получает свежий GitLab ID token без постоянного сервисного
ключа Collaborative. Не включайте CI_DEBUG_TRACE; токены не выводятся и не сохраняются
в артефакты. Assertion обменивается один раз без повтора; перезапустите задачу для
нового assertion. Сквозная проверка требует настроенной связи runner → Core.
